## 二、残留/后续项

以下为审计报告中的中低危项，本轮未做侵入式改动：

- **PQ-002 匿名安装器**：仍以 `install.lock` 为闸门。已有 Docker 默认 `INSTALL=false` 和部署文档约束；建议后续增加一次性安装令牌/CLI 安装，并在写 `.env` 前原子建锁。
- **PQ-007 dcat 通用表单反射/ACL**：属于自持 dcat fork 的供应商代码，需要单独发 fork 补丁并重新打 tag；默认单超管部署风险较低，但不建议让无角色管理员访问后台。
- **PQ-007-UPLOAD 上传扩展名**：依赖 dcat 上传字段服务端校验，出厂 nginx 已禁止 `/uploads`、`/storage` 下 PHP 执行；建议后续在 fork 中补 MIME/扩展名白名单。
- **PQ-008 ApiHook 盲 SSRF**：仅管理员可配置，属管理员已有能力；后续可加 https-only、私网 IP 拒绝和主机白名单。
- **PQ-009 后台 HTML 字段**：footer/notice/商品描述本身是后台“自定义 HTML”能力，需业务确认是否引入保存期 HTML 净化/CSP；本轮只修复了 textarea 直接拼接的 XSS。
- **HSTS / HTTP→HTTPS 跳转 / admin remember 期限**：属部署拓扑配置，部署手册已要求 HTTPS、`TRUSTED_PROXIES` 和 Secure Cookie；建议在入口 nginx 统一加 HSTS 和 301。

## 五、复核轮补充（check agent）

在提交前对上述整改做了一轮逐条复核，发现并修掉 5 处会真实影响支付/下单的缺陷（详细结论见会话报告）：

1. **PQ-004 汇率漂移**：`context` token 里的 `stripe_usd_amount` 原先在 check/charge/returnUrl 用
   `expectedUsdAmount()` 现算，而该函数每次都调 CMB 汇率接口；汇率一跳动，合法支付就会被判 `fail`。
   改为 `expectedUsdAmountForOrder()`：首次计算后按订单缓存（6h，缓存不可用则降级现算），金额仍完全由服务端决定。
2. **PQ-006 仍可绕过**：`['geetest_challenge' => 'geetest']` 对缺失字段是「跳过」而非「失败」，
   改为 `required|geetest`；同时把扩展规则体改为显式取参并 fail closed（原写法缺字段会 `Undefined array key` → 500）。
3. **PQ-003 查询密码路径**：`withEmailAndPassword()` 不应在已提供 `search_pwd` 时再用 cookie 订单号收窄结果，
   否则换浏览器/清 cookie 的客户查不到自己的订单。改为只在「无查询密码、仅靠 cookie」时使用 `whereIn`。
4. **PQ-001 连带 500**：`install.sql` 出厂全部渠道关闭后 `PayService::pays()` 返回 null，
   而 buy 视图直接 `@foreach($payways)`，PHP 8 下 `foreach(null)` 会被框架转成 500（全新安装的购买页）。
   改为恒返回数组。
5. **Stripe 收银台**：`gateway()` 不再回显原始异常文本（只记日志）；微信扫码轮询改 3s 一次并补 `error` 重试，
   避免 1s 轮询把自己打到 `throttle:30,1` 上后彻底停摆。

另外 `search-order-by-sn` 的 `input('order_sn')` 补了标量强转（null/数组会 TypeError）。

复核后验证：`php -l` 全部通过；PHPUnit `OK (41 tests, 147 assertions)`；`route:list -v` 与第三节一致；
`install.sql` / `upgrade-php83.sql` 在 MySQL 8.0 实跑通过：升级脚本连跑两次幂等；已配置凭据的易支付行保留原有开关，占位符/非易支付行保持 0。

## 六、最终复核补充

在复核轮之后又处理了以下几处边界：

- `processManual()` 已付款但库存不足时改为 `STATUS_ABNORMAL`，不再回滚成 `WAIT_PAY`，避免过期任务把已付款订单改成过期；异常单不计销量。
- `upgrade-php83.sql` 改为只关闭“非易支付/凭据为空或占位符”的行，已配置真实凭据的易支付行保留运营者原有开关；重复执行不会把刻意关闭的渠道重新打开。
- Stripe 收银台 URL 改用 `url()` 生成，支持子目录部署；卡支付成功后的 `return_url` 只带 `orderid` 时回订单详情，不再返回裸 `fail`。
- 邮件任务改为 `->afterCommit()`，避免事务回滚后仍发出邮件。
- PRD R5/AC3/AC4 已同步为“默认全部关闭，配置并手动启用易支付”。

最终验证：PHPUnit `41/41`、`147 assertions`；`php -l` 全部通过；`security-audit` 0 errors / 2 warnings；`install.sql` + `upgrade-php83.sql` 在 MySQL 8.0 连跑两次幂等。
